Injectiveは、DeFiアプリケーションの構成要素をネイティブなチェーンモジュールとして提供します。スタンドアロンのプロトコルコントラクトをデプロイして監査する代わりに、チェーンレベルですでに存在するインフラの上に構築できます。

## 利用できる機能

| 機能 | アクセス方法 | 実現できること |
|---|---|---|
| **Exchangeモジュール** | Solidityからの [Exchange precompile](/jp/developers-evm/precompiles)（`0x68`）、またはネイティブSDK | 注文の発注、orderbookの照会、ネイティブCLOBに対するスワップの実行 |
| **Bankモジュール** | Solidityからの [Bank precompile](/jp/developers-evm/bank-precompile)（`0x64`） | EVMとネイティブをまたぐトークンの送金、残高の照会、アローワンスの管理 |
| **Oracleモジュール** | [カスタムoracleプロバイダー](/jp/developers-defi/provider-oracle) | オフチェーンの価格フィードやアセット評価額をオンチェーンで公開 |
| **Subaccounts** | [トレーディングアカウント](/jp/developers/concepts/trading-account) | メインウォレット残高から分離された、独立したマージンとポジションの管理 |
| **保険基金** | [Insuranceモジュール](/developers-native/injective/insurance) | デリバティブマーケットの引受、清算時の不足分の吸収 |
| **Permissions** | [Permissionsモジュール](/developers-native/injective/permissions) | コンプライアンスゲート付きDeFiのためのロールベースのアクセス制御 |

## レンディングと担保付き借入

Injective上のレンディングプロトコルでは、次のものを利用できます:

1. 担保トークンの保有と送金のための **Bank precompile**
2. リアルタイムの担保評価のための **oracleフィード**（オンチェーン価格データ、またはoracleプロバイダーによるカスタムのオフチェーンフィード）
3. 清算のための **Exchange precompile**（担保比率が低下した際にCLOBに対してreduce-only注文を発注）
4. 参加者を制限するための **Permissionsモジュール**（規制対象のレンディングプロダクト向け）

Solidityのレンディングコントラクトはprecompileを介してこれらとやり取りするため、標準的なEVMコントラクトからネイティブモジュールの機能を利用できます。独自のoracleネットワーク、清算ボットのインフラ、orderbookを構築する必要はありません。

precompileのインターフェースとデプロイガイドについては、[EVM Precompiles](/jp/developers-evm/precompiles) を参照してください。

## Vaults

Vault戦略は、InjectiveのDeFiインフラに資本を投入することで利回りの獲得を自動化します:

- ネイティブCLOB上のマネージド戦略のための **[Mito](https://mito.fi) vault**
- exchange precompileを使用して取引の執行、ポジション管理、リバランスを行うSolidityの**カスタムvaultコントラクト**
- 独立したポジション管理のためにsubaccountを使用する**LP戦略**
