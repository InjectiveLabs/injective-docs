## トークンのオリジン

トークンは4つのオリジンのいずれかを通じてInjectiveに到達します。オリジンによって、denomの形式、メタデータを管理するアカウント、そしてトークンをEVMから参照可能にするために必要な手順が決まります。

| 出発点 | オリジン | Denom | リファレンス |
|---|---|---|---|
| 新しいトークン | **TokenFactory** | `factory/...` | このページ |
| 既存のEthereum ERC20 | **Peggy** | `peggy0x...` | [Bridge & Deploy](/developers-defi/bridge-deploy) |
| 他のIBCチェーン上のトークン | **IBC** | `ibc/...` | [IBC転送](/jp/developers-native/examples/ibc) |
| Injective EVM上にデプロイされたコントラクト | **Injective EVM** | `erc20:0x...` | [MultiVM Token Standard](/jp/developers-evm/multivm-token-standard) |

いずれのオリジンもbank denomを生成します。exchange、auction、insurance、permissionsの各モジュールはすべてbank denom上で動作するため、オリジンによってトークンの将来の用途が制限されることはありません。基盤となるモデルについては [MultiVM Token Standard](/jp/developers-evm/multivm-token-standard) を参照してください。

<Note>
コンプライアンスで制限されたアセットは、以下のTokenFactoryの手順に従い、その上にpermissions namespaceを重ねて構成します。ロール、ポリシー、KYCフックについては [Issue Permissioned Assets](/developers-defi/permissioned-assets) を参照してください。
</Note>

## 作成時に固定される設定

TokenFactory denomの以下3つのプロパティは、一度設定すると変更できません。

**Decimals** は、bankメタデータにゼロ以外の値が記録された後は変更できません。以降の変更は `cannot update denom metadata decimals` で失敗するため、誤った値は永続的に残ります。

**Admin burn** は `create-denom` の `--allow-admin-burn` で設定され、無効化することしかできません。一度falseになるか無効化されると、再度有効化しようとしても失敗します。falseの間は、どのアカウントも他のアドレスからburnできず、ペアとなるERC20は一切burnできません。ERC20のburnは、常にコントラクトからではなく保有者からのburnとしてチェーンに届くためです。このフラグを設定しただけでは、ペアのコントラクトにburnの権限は付与されません。そのためには、EVMアクセスの項で説明する別途のネイティブ権限が必要です。

**Admin権限** は、一度放棄すると回復できません。adminをゼロアドレス `inj1qqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqe2hm49` に設定すると供給量が凍結され、多くの場合それが意図された目的です。ただし同時に、`MsgSetDenomMetadata` を送信できる権限を持つ者がガバナンスを含めていなくなり、ペアのERC20が依存するmint権限も失われます。

## Denomの作成

作成手数料は作成者が支払い、ネットワークによって異なります。執筆時点では、mainnetで0.1 INJ、testnetで1 INJです。現在の値はモジュールのparamsに保持されています:

```bash
curl --fail --silent --show-error \
  "https://sentry.lcd.injective.network/injective/tokenfactory/v1beta1/params" | jq
```

### Webアプリケーション

[Injective Hub](https://injhub.com/token-factory/) と [DojoSwap](https://docs.dojo.trading/) はいずれもトークンの作成・管理が可能で、そのトークンのマーケットを立ち上げることもできます。[TokenStation](https://www.tokenstation.app/) はエアドロップやローンチ用のツールを提供しています。

### injectived

```bash
CHAIN_ID="injective-888"
NODE="https://testnet.sentry.tm.injective.network:443"
ADMIN_KEY="admin"
ADMIN=$(injectived keys show "$ADMIN_KEY" -a)
TX="--from=$ADMIN_KEY --chain-id=$CHAIN_ID --node=$NODE --gas-prices=500000000inj --gas=1000000"

# create-denom [subdenom] [name] [symbol] [decimals]
injectived tx tokenfactory create-denom ak "AK Coin" AKK 6 --allow-admin-burn $TX

DENOM="factory/${ADMIN}/ak"
```

Denomは作成者アドレスによって名前空間が区切られるため、作成はパーミッションレスで、名前の衝突も発生しません。mainnetでは、対応する値は `--chain-id=injective-1` と `--node=https://sentry.tm.injective.network:443` です。

### SDKとコントラクト

- **TypeScript:** [TokenFactory SDKの例](/jp/developers-native/examples/token-factory)
- **Wasmコントラクト:** [`injective-cosmwasm`](https://github.com/InjectiveLabs/cw-injective) は `create_new_denom_msg`、`create_set_token_metadata_msg`、`create_mint_tokens_msg`、`create_burn_tokens_msg` を提供しています
- **メッセージリファレンス:** [TokenFactoryメッセージ](/developers-native/injective/tokenfactory/03_messages)

## メタデータ

ウォレット、エクスプローラー、Solidityの呼び出し元は、name、symbol、decimalsをbankメタデータから読み取ります。メタデータのないdenomは、空白かつdecimalsゼロとして表示されます。

```bash
# set-denom-metadata [description] [base] [display] [name] [symbol] \
#                    [uri] [uri-hash] [denom-unit (json)] [decimals] [shouldDisableAdminBurn]
injectived tx tokenfactory set-denom-metadata \
  "My token description" "$DENOM" AKK "AK Coin" AKK "" "" \
  "[{\"denom\":\"$DENOM\",\"exponent\":0,\"aliases\":[]},
    {\"denom\":\"AKK\",\"exponent\":6,\"aliases\":[]}]" \
  6 false $TX
```

このコマンドは10個の位置引数を取ります。最後の引数を `true` にすると、admin burnが永続的に無効化されます。

各フィールドについては [Token metadata](/developers/assets/token-metadata) を参照してください。

## 供給量

```bash
# mint [amount] [receiver]
injectived tx tokenfactory mint "1000000$DENOM" "$ADMIN" $TX

# burn [amount] [burn_from]
injectived tx tokenfactory burn "1000000$DENOM" "$ADMIN" $TX
```

どちらのコマンドも2つの引数を取ります。decimalsが6の場合、上記の量は1トークンに相当します。

## EVMアクセス

TokenFactory denomは、ERC20ペアが登録されるまでMetaMaskやSolidityコントラクトからは参照できません。

```bash
injectived tx erc20 create-token-pair "$DENOM" --from="$ADMIN_KEY" \
  --chain-id="$CHAIN_ID" --node="$NODE" --gas=3000000 --gas-prices=160000000inj
```

ペアの作成にはゼロ以外の供給量が必要なため、初回のmintの後に行います。`--erc20` を省略すると、チェーンはペア作成者が所有する `MintBurnBankERC20` をデプロイします。代わりにコントラクトアドレスを指定する場合は追加の制約があり、[ERC20 Module](/jp/developers-evm/erc20-module) で説明しています。

ペアを登録しても、コントラクトが変更されたり、ネイティブ権限が付与されたり、メタデータの管理者が変わったりすることはありません。denomとアドレスの間のマッピングが記録されるだけです。

<Warning>
ERC20の所有権はネイティブのmint権限を付与しません。precompileはネイティブのmintを **コントラクトアドレス** をsenderとして送信するため、ネイティブのチェックはEVMの呼び出し元ではなくそのアドレスに対して適用されます。permissions namespaceがない場合、そのアドレスはdenom adminである必要があります。namespaceがある場合は `MINT` を保持している必要があり、denom adminであるだけでは不十分です。

burnはさらに厳格です。denomに `allow_admin_burn` が追加で必要となり、namespaceが存在する場合は `BURN` ではなく `SUPER_BURN` が必要です。[mintとburnの権限](/jp/developers-evm/erc20-module#mintとburnの権限) を参照してください。
</Warning>

## ディスカバリー

オンチェーンのメタデータだけでは、トークンはdAppのフロントエンドに表示されません。フロントエンドはレジストリから情報を読み取るためです。[injective-lists](https://github.com/InjectiveLabs/injective-lists/blob/master/CONTRIBUTING.md) はInjective dApp全体にロゴとラベルを提供しており、[Injective List](/developers/assets/injective-list) で説明しています。

シンボルはトークン間で一意ではありません。統合手順においてアセットを一意に識別できるのは、ネットワーク、bank denom、ERC20アドレスの組み合わせのみです。

## マーケット

供給量が存在し、メタデータが設定されていれば、ネイティブorderbook上にスポットマーケットを作成できます。[マーケットの立ち上げ](/jp/developers-defi/market-launch) を参照してください。
