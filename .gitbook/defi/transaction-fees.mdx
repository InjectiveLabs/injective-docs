On the Native Execution Layer, gas measures the work a transaction consumes, including signature checks, state reads and writes, and message execution. A transaction declares a gas limit (`gasWanted`) and pays a fee in INJ. Gas used (`gasUsed`) reports how much of the limit execution consumed.

## Native transaction fees

When you set a gas price, multiply the gas limit by that price to calculate the fee, then round up to the nearest base unit if needed. The **`inj`** denomination uses 18 decimals. For example, a gas limit of `104,519` at `160,000,000` base units per gas gives `0.00001672304 INJ`.

The transaction gas meter tracks work against the declared limit. The block gas meter tracks work across transactions in a block and enforces the block gas limit. Transaction checks happen before the messages execute. Modules can also do work at the beginning and end of each block.

## Exchange transaction gas

Order placement, cancellation, and batch operations have different gas requirements. Use the [Exchange Gas Heuristics](/developers-native/injective/exchange/12_gas_heuristics) to estimate gas for native exchange transactions, including post only orders and orders with an expiry block. Simulate the full transaction before submitting it.

For exchange trading fees, see [Trading Fees and Rebates](/defi/trading/fees).
