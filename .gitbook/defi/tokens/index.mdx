Injective provides a variety of different token standards one can use when creating a dApp. In this document, we will cover the different types of tokens, as well as recommendations and guidance for using each.

## Denom

A denom is how assets are represented within the Bank module of Injective. These assets can be used for trading, creating new markets on the exchange module, participating in auctions, transferring to another address, etc.

Depending on the origin of the denom and how it was created on Injective, we have different types of denoms:

| Denom type | Format | Origin |
|---|---|---|
| **Native** | `inj` | The native coin of Injective. Also the Injective EVM gas token |
| **Factory** | `factory/{creator}/{subdenom}` | Created permissionlessly via [TokenFactory](/defi/tokens/token-factory) |
| **Peggy** | `peggy0x{ERC20_CONTRACT_ADDRESS}` | Bridged from Ethereum via the [Peggy bridge](/developers-native/bridges/ethereum) |
| **IBC** | `ibc/{hash}` | Bridged from another IBC chain |
| **EVM** | `erc20:0x{CONTRACT_ADDRESS}` | Deployed directly on the Injective EVM against the [Bank precompile](/developers-evm/bank-precompile) |
| **Insurance fund** | `share{id}` | Token shares of an insurance fund |

Each of the above has a registered bank denom, which is what the native exchange, auction, insurance and permissions
modules rely on as the single source of truth. Under the [MultiVM Token Standard](/developers-evm/multivm-token-standard),
a denom with a registered token pair can also be called from the EVM. The [erc20 module](/developers-evm/erc20-module)
maps the denom to an ERC20 contract address, and calls to that contract resolve through the
[Bank precompile](/developers-evm/bank-precompile) to the same bank balance. EVM dApps interact with the paired
address as a standard ERC20. There is no second balance to bridge or reconcile.

<Note>
CW20 assets are **not** native bank denoms. Their balances live in contract storage. An existing CW20 can be
represented as a factory denom of the form `factory/{CW20_ADAPTER_CONTRACT}/{CW20_CONTRACT_ADDRESS}`
through the [CW20 adapter](/developers-cosmwasm/cw20-adapter), but CW20 is not recommended for new
integrations and is planned for deprecation.
</Note>
