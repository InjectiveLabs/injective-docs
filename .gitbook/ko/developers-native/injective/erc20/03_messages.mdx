# 메시지

이 섹션에서는 `erc20` 모듈 메시지의 처리와 해당 상태 업데이트에 대해 설명합니다.

### 토큰 페어 생성: `MsgCreateTokenPair`

기존 bank denom과 새로운 또는 기존 ERC20 스마트 컨트랙트 간의 연결을 생성합니다.
ERC20 주소가 비어 있으면 새로운 ERC20 스마트 컨트랙트가 인스턴스화됩니다. 모든 bank denom이 지원되는 것은 아닙니다.

유효성 검사 규칙:

- tokenfactory denom의 경우, denom admin 또는 governance authority만 토큰 페어를 생성할 수 있습니다
- peggy 및 IBC denom의 경우, 누구나 토큰 페어를 생성할 수 있으며 ERC20 주소는 비어 있어야 합니다

```go
type MsgCreateTokenPair struct {
	Sender    string   
	TokenPair TokenPair
}

type TokenPair struct {
	BankDenom    string
	Erc20Address string
}
```

**상태 수정:**

- 유효성 검사:
	- bank denom 또는 ERC20 주소에 대한 토큰 페어가 아직 존재하지 않는지 확인
	- 제공된 bank denom이 존재하고 공급량이 0이 아닌지 확인, 그렇지 않으면 `ErrUnknownBankDenom`
	- Sender가 이 denom에 대한 토큰 페어를 생성할 권한이 있는지 확인 (tokenfactory denom의 경우 denom admin 또는 governance authority)
	- ERC20 주소가 제공된 경우:
		- 계정이 존재하고 컨트랙트 코드를 보유하고 있는지 확인
		- 파생된 `erc20:0x...` denom에 유통 공급량과 bank 메타데이터가 모두 없는지 확인, 그렇지 않으면 `ErrExistingERC20DenomSupply`
		- 300,000 가스 한도 내에서 `symbol()` 메서드를 호출하여 컨트랙트가 ERC20인지 확인
- bank denom 유형에 따라 연결 생성:
	- tokenfactory denom:
		- permissions 네임스페이스가 존재하는 경우 이를 읽고 MINT, BURN 또는 SUPER_BURN 정책이 비활성화되어 있는지 확인
		- 세 가지 중 하나라도 비활성화되어 있으면 새로운 `FixedSupplyBankERC20`을 인스턴스화하고 제공된 ERC20 주소는 거부
		- 그렇지 않은 경우, ERC20 주소가 제공되지 않았다면 메시지 sender가 소유하는 새로운 `MintBurnBankERC20`을 인스턴스화하고, 제공되었다면 해당 주소 사용
		- 연결 저장
	- IBC 및 peggy denom:
		- 새로운 `FixedSupplyBankERC20` 스마트 컨트랙트 인스턴스화
		- 연결 저장

<Note>
`ErrExistingERC20DenomSupply` 검사는 오류 이름과 달리 **공급량 또는 메타데이터**를 모두 다룹니다. 생성자에서 `setMetadata`를 호출한 커스텀 컨트랙트는 이미 `erc20:0x...` 메타데이터를 기록했으므로 공급량이 0이더라도 거부됩니다. 커스텀 컨트랙트에 대한 전체 요구 사항은
[ERC20 모듈](/ko/developers-evm/erc20-module)을 참조하세요.
</Note>

### 토큰 페어 삭제: `MsgDeleteTokenPair`

현재 authority만 페어의 bank denom을 제공하여 토큰 페어를 제거할 수 있습니다.

```go
type MsgDeleteTokenPair struct {
	Sender    string
	BankDenom string
}
```
