## 아키텍처

Injective는 비잔틴 장애 허용(BFT) 메커니즘을 갖춘 CometBFT(구 Tendermint) 합의를 사용하여 1초 미만의 최종성을 달성합니다. 네트워크는 높은 처리량의 트레이딩 활동을 처리하기 위해 엔터프라이즈급 사양(128GB RAM, 고클럭 CPU, NVMe 스토리지)의 베어메탈 서버를 요구합니다.

### 노드 유형

| 노드 | 역할 |
|------|------|
| **검증자 노드** | 블록을 제안하고 투표하여 합의에 참여합니다. 담보로 스테이킹된 INJ와 고가용성 하드웨어가 필요합니다. |
| **[센트리 노드](/ko/developers/concepts/sentry-node)** | 트래픽을 중계하여 검증자를 직접적인 퍼블릭 노출로부터 보호하는 풀 노드로, 검증자와 퍼블릭 네트워크 사이의 게이트웨이 역할을 합니다. |

### 핵심 구성 요소

| 구성 요소 | 목적 |
|-----------|---------|
| **[Cosmovisor](/ko/infra/cosmovisor)** | 체인 바이너리 업그레이드를 자동화하는 프로세스 관리자로, 거버넌스 승인 업그레이드 시 무중단 전환을 가능하게 합니다. 설정은 [노드 운영](/ko/infra/run-node)을 참조하세요. |
| **[Peggo](/ko/infra/validator-mainnet/peggo)** | Ethereum과 Injective 간 메시지를 중계하는 브릿지 오케스트레이터입니다. 검증자에게 필수입니다. |
| **[WebSocket 서버](https://github.com/InjectiveFoundation/injective-core)** | gRPC Chain Stream 서버를 래핑하여 표준 WebSocket 연결로 실시간 체인 이벤트를 스트리밍합니다. |

### 체인 업그레이드

Injective는 미리 정해진 블록 높이에서 주기적으로 조정 소프트웨어 업그레이드를 진행합니다. 합의를 유지하려면 모든 노드가 새 바이너리로 전환해야 합니다. 절차는 [업그레이드](/ko/infra/upgrade-node)를, 문제 해결은 [조정 업그레이드](/ko/infra/coordinated-upgrades) 가이드를 참조하세요.
