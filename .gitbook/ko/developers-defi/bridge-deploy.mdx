## 단계별 안내

<img src="/img/bridge-deploy-flow.svg" alt="Bridge and deploy flow: Ethereum to Injective" />

### 1. Peggy를 통한 브릿징

Peggy 브릿지 컨트랙트를 사용하여 ERC-20 토큰을 Ethereum에서 Injective로 전송하세요.

Ethereum에서 두 개의 트랜잭션이 필요합니다:
1. Peggy 컨트랙트가 토큰을 사용할 수 있도록 **Approve**
2. 토큰 주소, Injective 주소, 금액과 함께 Peggy 컨트랙트에서 **sendToInjective** 호출

특정 ERC-20에 대한 첫 번째 브릿지 트랜잭션은 Injective에 `peggy0x{CONTRACT_ADDRESS}` 형식으로 denom을 자동으로 생성합니다.

<Info>
Peggo 릴레이어는 일반적으로 2분 이내에 입금을 처리합니다. [Injective 테스트넷 익스플로러](https://testnet.explorer.injective.network) 또는 REST API를 통해 잔액을 확인할 수 있습니다.
</Info>

자세한 내용은 [Peggy 브릿지 가이드](/ko/developers-native/bridges/ethereum)를 참조하세요.

### 2. MTS 토큰 페어 생성

Peggy denom을 EVM 측(MetaMask, Solidity 컨트랙트, Blockscout)에서 접근할 수 있도록 토큰 페어를 생성하세요.

```bash
injectived tx erc20 create-token-pair \
  "peggy0xYOUR_TOKEN_ADDRESS" \
  --from=YOUR_KEY \
  --keyring-backend=file \
  --chain-id=injective-888 \
  --node=https://testnet.sentry.tm.injective.network:443 \
  --gas=3000000 \
  --gas-prices=160000000inj \
  --yes
```

<Warning>
**가스 요구 사항:** 이 트랜잭션은 최소 `--gas=3000000`이 필요합니다. ERC20 모듈은 내부적으로 2M 가스 한도가 하드코딩된 EVM 컨트랙트를 배포합니다. 약 2.1M 미만의 가스 값은 `gas computation overflow/underflow` 에러로 실패합니다.
</Warning>

Peggy denom의 경우 **누구나** 토큰 페어를 생성할 수 있습니다 - 관리자 권한이 필요하지 않습니다. 모듈이 `FixedSupplyBankERC20` 컨트랙트를 자동으로 배포합니다.

트랜잭션이 성공하면 새 ERC20 주소를 조회하세요:

```bash
curl -s "https://testnet.sentry.lcd.injective.network:443/injective/erc20/v1beta1/all_token_pairs" \
  | jq '.token_pairs[] | select(.bank_denom | contains("YOUR_TOKEN_ADDRESS"))'
```

자세한 내용은 [ERC20 모듈 문서](/ko/developers-evm/erc20-module)를 참조하세요.

### 3. 토큰 메타데이터 설정

토큰 메타데이터(이름, 심볼, 소수점 자릿수)는 MetaMask, Blockscout 및 컨트랙트에서 `symbol()`, `name()`, `decimals()`를 호출하는 모든 EVM 도구에서 토큰이 표시되는 방식을 결정합니다.

<Warning>
Peggy로 브릿징된 토큰은 Ethereum의 메타데이터를 자동으로 상속받지 않습니다. MTS ERC20 컨트랙트는 Injective의 bank 모듈에서 메타데이터를 읽습니다. bank 메타데이터가 설정되어 있지 않으면 토큰은 빈 이름, 빈 심볼, 0 소수점 자릿수로 표시됩니다.
</Warning>

**Peggy denom(`peggy0x...`)의 경우:** 메타데이터는 [거버넌스 제안](/ko/developers/testnet-proposals)을 통해 설정해야 합니다. Peggy denom에는 관리자 권한이 없기 때문입니다 - 거버넌스만이 bank 모듈의 메타데이터 저장소에 쓸 수 있습니다. 전체 제안 템플릿과 테스트넷 검증자 투표를 위해 팀과 조율하는 방법은 [토큰 메타데이터 가이드](/ko/developers/assets/token-metadata)를 참조하세요.

**TokenFactory denom(`factory/...`)의 경우:** denom 관리자가 `MsgSetDenomMetadata`를 직접 호출할 수 있습니다. [TokenFactory 예제](/developers-native/examples/token-factory)를 참조하세요.

**Injective dApp의 프론트엔드 표시를 위해:** [injective-lists](https://github.com/InjectiveLabs/injective-lists/blob/master/CONTRIBUTING.md)에 토큰을 제출하세요. 이는 온체인 메타데이터와 별개이며 MetaMask나 Blockscout에는 영향을 주지 않습니다.
