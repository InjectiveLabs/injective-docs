## 토큰 출처

토큰은 네 가지 출처 중 하나를 통해 Injective에 도달합니다. 출처에 따라 denom 형식, 메타데이터를 제어하는 계정,
그리고 토큰을 EVM에서 볼 수 있도록 하는 데 필요한 사항이 결정됩니다.

| 시작점 | 출처 | Denom | 참조 |
|---|---|---|---|
| 새 토큰 | **TokenFactory** | `factory/...` | 이 페이지 |
| 기존 Ethereum ERC20 | **Peggy** | `peggy0x...` | [Bridge & Deploy](/developers-defi/bridge-deploy) |
| 다른 IBC 체인의 토큰 | **IBC** | `ibc/...` | [IBC 전송](/developers-native/examples/ibc) |
| Injective EVM에 배포된 컨트랙트 | **Injective EVM** | `erc20:0x...` | [MultiVM Token Standard](/ko/developers-evm/multivm-token-standard) |

각 출처는 bank denom을 생성합니다. exchange, auction, insurance 및 permissions 모듈은 모두 bank denom을 기반으로
작동하므로, 출처가 토큰의 이후 용도를 제한하지 않습니다.
[MultiVM Token Standard](/ko/developers-evm/multivm-token-standard)에서 기본 모델을 설명합니다.

<Note>
컴플라이언스 제한 자산은 아래의 TokenFactory 절차를 따르되 그 위에 permissions 네임스페이스를 추가합니다.
[Issue Permissioned Assets](/developers-defi/permissioned-assets)에서 역할, 정책 및 KYC 훅을 다룹니다.
</Note>

## 생성 시 고정되는 설정

TokenFactory denom의 세 가지 속성은 한 번 설정되면 변경할 수 없습니다.

**Decimals**는 bank 메타데이터에 0이 아닌 값이 기록된 후에는 변경할 수 없습니다. 이후 변경은
`cannot update denom metadata decimals` 오류로 실패하므로, 잘못된 값은 영구적으로 남습니다.

**Admin burn**은 `create-denom`의 `--allow-admin-burn`으로 설정되며, 끄는 것만 가능합니다.
한 번 false이거나 비활성화되면 다시 활성화할 수 없습니다. false인 동안에는 어떤 계정도 다른 주소에서 소각할 수 없으며,
페어링된 ERC20은 전혀 소각할 수 없습니다. ERC20 소각은 항상 컨트랙트가 아닌 보유자로부터의 소각으로 체인에 도달하기
때문입니다. 이 플래그를 설정하는 것만으로 페어링된 컨트랙트에 소각 권한이 부여되지는 않습니다. 이를 위해서는 EVM 액세스에서
설명하는 별도의 네이티브 권한이 필요합니다.

**Admin 권한**은 한 번 포기하면 복구할 수 없습니다. admin을 제로 주소
`inj1qqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqe2hm49`로 설정하면 공급량이 고정되며, 이는 흔히 의도된 결과입니다. 동시에
거버넌스를 포함하여 `MsgSetDenomMetadata`를 보낼 권한이 있는 발신자가 없어지며, 페어링된 ERC20이 의존하는 발행 권한도
제거됩니다.

## Denom 생성

생성 수수료는 생성자가 지불하며 네트워크마다 다릅니다. 작성 시점 기준으로 메인넷에서는 0.1 INJ, 테스트넷에서는
1 INJ입니다. 현재 값은 모듈 파라미터에 저장되어 있습니다:

```bash
curl --fail --silent --show-error \
  "https://sentry.lcd.injective.network/injective/tokenfactory/v1beta1/params" | jq
```

### 웹 애플리케이션

[Injective Hub](https://injhub.com/token-factory/)와 [DojoSwap](https://docs.dojo.trading/)은 모두
토큰을 생성 및 관리하고 해당 토큰의 마켓을 출시할 수 있습니다.
[TokenStation](https://www.tokenstation.app/)은 에어드롭 및 출시 도구를 추가로 제공합니다.

### injectived

```bash
CHAIN_ID="injective-888"
NODE="https://testnet.sentry.tm.injective.network:443"
ADMIN_KEY="admin"
ADMIN=$(injectived keys show "$ADMIN_KEY" -a)
TX="--from=$ADMIN_KEY --chain-id=$CHAIN_ID --node=$NODE --gas-prices=500000000inj --gas=1000000"

# create-denom [subdenom] [name] [symbol] [decimals]
injectived tx tokenfactory create-denom ak "AK Coin" AKK 6 --allow-admin-burn $TX

DENOM="factory/${ADMIN}/ak"
```

Denom은 생성자 주소로 네임스페이스화되므로 생성이 무허가로 이루어지고 이름 충돌이 발생하지 않습니다. 메인넷에서의
해당 값은 `--chain-id=injective-1` 및 `--node=https://sentry.tm.injective.network:443`입니다.

### SDK 및 컨트랙트

- **TypeScript:** [TokenFactory SDK 예제](/ko/developers-native/examples/token-factory)
- **Wasm 컨트랙트:** [`injective-cosmwasm`](https://github.com/InjectiveLabs/cw-injective)은 `create_new_denom_msg`, `create_set_token_metadata_msg`, `create_mint_tokens_msg` 및 `create_burn_tokens_msg`를 제공합니다
- **메시지 참조:** [TokenFactory 메시지](/ko/developers-native/injective/tokenfactory/03_messages)

## 메타데이터

지갑, 익스플로러 및 Solidity 호출자는 bank 메타데이터에서 name, symbol 및 decimals를 읽습니다. 메타데이터가 없는
denom은 빈 값과 0 decimals로 표시됩니다.

```bash
# set-denom-metadata [description] [base] [display] [name] [symbol] \
#                    [uri] [uri-hash] [denom-unit (json)] [decimals] [shouldDisableAdminBurn]
injectived tx tokenfactory set-denom-metadata \
  "My token description" "$DENOM" AKK "AK Coin" AKK "" "" \
  "[{\"denom\":\"$DENOM\",\"exponent\":0,\"aliases\":[]},
    {\"denom\":\"AKK\",\"exponent\":6,\"aliases\":[]}]" \
  6 false $TX
```

이 명령은 10개의 위치 인수를 받습니다. 마지막 인수가 `true`이면 admin burn이 영구적으로 비활성화됩니다.

각 필드에 대한 설명은 [토큰 메타데이터](/ko/developers/assets/token-metadata)를 참조하세요.

## 공급량

```bash
# mint [amount] [receiver]
injectived tx tokenfactory mint "1000000$DENOM" "$ADMIN" $TX

# burn [amount] [burn_from]
injectived tx tokenfactory burn "1000000$DENOM" "$ADMIN" $TX
```

두 명령 모두 두 개의 인수를 받습니다. 6 decimals 기준으로 위의 양은 토큰 1개를 나타냅니다.

## EVM 액세스

TokenFactory denom은 ERC20 페어가 등록되기 전까지 MetaMask나 Solidity 컨트랙트에서 보이지 않습니다.

```bash
injectived tx erc20 create-token-pair "$DENOM" --from="$ADMIN_KEY" \
  --chain-id="$CHAIN_ID" --node="$NODE" --gas=3000000 --gas-prices=160000000inj
```

페어 생성에는 0이 아닌 공급량이 필요하므로 초기 발행 이후에 수행합니다. `--erc20`을 생략하면 체인은 페어 생성자가
소유하는 `MintBurnBankERC20`을 배포합니다. 대신 컨트랙트 주소를 제공하는 경우 추가 제약 조건이 적용되며, 이는
[ERC20 모듈](/ko/developers-evm/erc20-module)에 설명되어 있습니다.

페어를 등록해도 컨트랙트가 변경되거나, 컨트랙트에 네이티브 권한이 부여되거나, 메타데이터를 제어하는 주체가 바뀌지
않습니다. 단지 denom과 주소 간의 매핑을 기록할 뿐입니다.

<Warning>
ERC20 소유권은 네이티브 발행 권한을 부여하지 않습니다. precompile은 **컨트랙트 주소**를 발신자로 하여 네이티브 발행을
제출하므로, 네이티브 검사는 EVM 호출자가 아닌 해당 주소에 적용됩니다. permissions 네임스페이스가 없으면 해당 주소가
denom admin이어야 합니다. 네임스페이스가 있으면 `MINT`를 보유해야 하며, denom admin인 것만으로는 충분하지 않습니다.

소각은 더 엄격합니다. denom에 `allow_admin_burn`이 추가로 필요하며, 네임스페이스가 있는 경우 `BURN`이 아닌
`SUPER_BURN`이 필요합니다.
[발행 및 소각 권한](/ko/developers-evm/erc20-module#민트-및-버닝-권한)을 참조하세요.
</Warning>

## 검색 노출

온체인 메타데이터만으로는 토큰이 dApp 프론트엔드에 표시되지 않습니다. 프론트엔드는 레지스트리에서 데이터를 읽습니다.
[injective-lists](https://github.com/InjectiveLabs/injective-lists/blob/master/CONTRIBUTING.md)는
Injective dApp 전반에 로고와 레이블을 제공하며, [Injective List](/ko/developers/assets/injective-list)에
문서화되어 있습니다.

심볼은 토큰 간에 고유하지 않습니다. 통합 안내에서는 네트워크, bank denom 및 ERC20 주소로만 자산을 명확하게
식별할 수 있습니다.

## 마켓

공급량이 존재하고 메타데이터가 설정되면 네이티브 오더북에 현물 마켓을 생성할 수 있습니다.
[마켓 출시](/ko/developers-defi/market-launch)를 참조하세요.
