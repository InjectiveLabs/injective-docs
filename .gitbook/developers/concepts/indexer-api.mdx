The Injective Indexer turns chain events into data that applications can query and stream, including markets, orders, trades, and account activity. It stores the indexed data in MongoDB so applications can look up historical records and subscribe to updates without replaying blocks themselves.

For endpoint definitions and request and response schemas, see the [Indexer API reference](https://api.injective.exchange/#indexer-api) and [Indexer Swagger UI](https://sentry.exchange.grpc-web.injective.network/swagger/#/).

## How the Indexer works

The diagram shows the Docker Compose deployment. **Exchange indexer services** groups Exchange Process, its database, and Exchange API. Trading apps consume that API from outside the deployment. Event Provider and optional Explorer use the same process-and-API pattern. The three named databases share one MongoDB replica set in the example deployment.

![Injective Indexer deployment showing node and asset-service inputs, Event Provider, Exchange and Explorer services, and client API protocols.](/img/indexer-architecture.svg)

- **Ingest and replay.** Event Provider fetches committed blocks and execution results from the node over CometBFT JSON-RPC and queries staking validator data over Cosmos gRPC. Exchange and Explorer consume the Event Provider API over gRPC and resume from their own saved block heights. A shared Event Provider can replace the local Event Provider pair. Its retained block range must cover every consumer's catch-up window.
- **Index and serve.** Exchange Process builds records for markets, orders, trades, and accounts. Explorer Process indexes blocks and transactions. Their APIs query those records and use MongoDB change streams for supported subscriptions. Applications use the node's native endpoints for direct chain queries and transaction submission. See [Indexer queries](/developers-native/query-indexer), [Indexer streams](/developers-native/query-indexer-stream), and [public endpoints](/infra/public-endpoints).
- **External dependencies.** Exchange Process and Exchange API call the **Asset Service** for token denomination metadata. The [mainnet Compose environment](https://github.com/InjectiveLabs/injective-indexer-releases/blob/master/docker/.env.mainnet.example#L36-L38) points to Injective-hosted endpoints and uses gRPC by default, with HTTP available as an option. Exchange Process also uses the node's LCD REST endpoint to reload market state during reconciliation. That migration needs an archival LCD that can serve the last indexed height. See the [market reconciliation steps](https://github.com/InjectiveLabs/injective-indexer-releases/blob/master/docker/CHANGELOG.md#mainnet).

## Service setup

Run your own stack if your trading app, explorer, or analytics service needs dedicated API capacity or control over data retention and backfills. For development or integrations that can use hosted services, start with the [public endpoints](/infra/public-endpoints).

The original [Indexer Service Setup Guide](https://app.notion.com/p/7e59980634d54991862300670583d46a) is available in Notion.

Get the Docker Compose files for Event Provider, Exchange, and optional Explorer from the [Injective Indexer Releases repository](https://github.com/InjectiveLabs/injective-indexer-releases). Check [Software Compatibility](/infra/software-compatibility) for the Indexer version listed for your chain release.

Follow the [Docker setup and migration guide](https://github.com/InjectiveLabs/injective-indexer-releases/blob/master/docker/README.md) to connect a node and start the services. For an existing deployment, review the [migration steps](https://github.com/InjectiveLabs/injective-indexer-releases/blob/master/docker/README.md#existing-installations) before applying the updated Compose files.
