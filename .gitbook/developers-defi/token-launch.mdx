## Token Origins

A token reaches Injective through one of four origins. The origin determines the denom format, which
account controls metadata, and what is required to make the token visible to the EVM.

| Starting point | Origin | Denom | Reference |
|---|---|---|---|
| A new token | **TokenFactory** | `factory/...` | This page |
| An existing Ethereum ERC20 | **Peggy** | `peggy0x...` | [Bridge & Deploy](/developers-defi/bridge-deploy) |
| A token on another IBC chain | **IBC** | `ibc/...` | [IBC transfers](/developers-native/examples/ibc) |
| A contract deployed on Injective EVM | **Injective EVM** | `erc20:0x...` | [MultiVM Token Standard](/developers-evm/multivm-token-standard) |

Each origin produces a bank denom. The exchange, auction, insurance and permissions modules all operate
on bank denoms, so origin does not constrain what a token can later be used for.
[MultiVM Token Standard](/developers-evm/multivm-token-standard) describes the underlying model.

<Note>
Compliance gated assets follow the TokenFactory sequence below with a permissions namespace layered on
top. [Issue Permissioned Assets](/developers-defi/permissioned-assets) covers roles, policies and KYC
hooks.
</Note>

## Settings Fixed at Creation

Three properties of a TokenFactory denom cannot be changed once set.

**Decimals** cannot be changed after bank metadata records a non-zero value. Later changes fail with
`cannot update denom metadata decimals`, so an incorrect value is permanent.

**Admin burn** is set by `--allow-admin-burn` on `create-denom` and can only ever be turned off.
Re-enabling it fails once it is false or has been disabled. While false, no account can burn from
another address, and a paired ERC20 cannot burn at all, since an ERC20 burn always reaches the chain
as a burn from the holder rather than from the contract. Setting the flag does not by itself authorize
the paired contract to burn; that requires the separate native authority described under EVM Access.

**Admin authority** is unrecoverable once renounced. Setting the admin to the zero address
`inj1qqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqe2hm49` freezes supply, which is frequently the intent. It also
leaves `MsgSetDenomMetadata` with no authorized sender, governance included, and removes the mint
authority that a paired ERC20 depends on.

## Creating the Denom

The creation fee is paid by the creator and differs between networks. At time of writing it is 0.1 INJ
on mainnet and 1 INJ on testnet. The current value is held in the module params:

```bash
curl --fail --silent --show-error \
  "https://sentry.lcd.injective.network/injective/tokenfactory/v1beta1/params" | jq
```

### Web applications

[Injective Hub](https://injhub.com/token-factory/) and [DojoSwap](https://docs.dojo.trading/) both
create and manage tokens and can launch a market for them.
[TokenStation](https://www.tokenstation.app/) adds airdrop and launch tooling.

### injectived

```bash
CHAIN_ID="injective-888"
NODE="https://testnet.sentry.tm.injective.network:443"
ADMIN_KEY="admin"
ADMIN=$(injectived keys show "$ADMIN_KEY" -a)
TX="--from=$ADMIN_KEY --chain-id=$CHAIN_ID --node=$NODE --gas-prices=500000000inj --gas=1000000"

# create-denom [subdenom] [name] [symbol] [decimals]
injectived tx tokenfactory create-denom ak "AK Coin" AKK 6 --allow-admin-burn $TX

DENOM="factory/${ADMIN}/ak"
```

Denoms are namespaced by creator address, which makes creation permissionless and removes name
collisions. On mainnet the equivalent values are `--chain-id=injective-1` and
`--node=https://sentry.tm.injective.network:443`.

## Metadata

Wallets, explorers and Solidity callers read name, symbol and decimals from bank metadata. A denom
without metadata displays blank with zero decimals.

```bash
# set-denom-metadata [description] [base] [display] [name] [symbol] \
#                    [uri] [uri-hash] [denom-unit (json)] [decimals] [shouldDisableAdminBurn]
injectived tx tokenfactory set-denom-metadata \
  "My token description" "$DENOM" AKK "AK Coin" AKK "" "" \
  "[{\"denom\":\"$DENOM\",\"exponent\":0,\"aliases\":[]},
    {\"denom\":\"AKK\",\"exponent\":6,\"aliases\":[]}]" \
  6 false $TX
```

The command takes ten positional arguments. The final one permanently disables admin burn when `true`.

[Token metadata](/developers/assets/token-metadata) documents the individual fields.

## Supply

```bash
# mint [amount] [receiver]
injectived tx tokenfactory mint "1000000$DENOM" "$ADMIN" $TX

# burn [amount] [burn_from]
injectived tx tokenfactory burn "1000000$DENOM" "$ADMIN" $TX
```

Both commands take two arguments. At six decimals, the amounts above represent one token.

## EVM Access

A TokenFactory denom is not visible to MetaMask or Solidity contracts until an ERC20 pair is registered
for it.

```bash
injectived tx erc20 create-token-pair "$DENOM" --from="$ADMIN_KEY" \
  --chain-id="$CHAIN_ID" --node="$NODE" --gas=3000000 --gas-prices=160000000inj
```

Pair creation requires non-zero supply, so it follows the initial mint. With `--erc20` omitted, the
chain deploys a `MintBurnBankERC20` owned by the pair creator. Supplying a contract address instead is
subject to further constraints, documented in [ERC20 Module](/developers-evm/erc20-module).

Registering a pair does not alter the contract, grant it any native authority, or change who controls
metadata. It records a mapping between the denom and the address, and nothing else.

<Warning>
ERC20 ownership does not confer native mint authority. The precompile submits native mints with the
**contract address** as sender, so the native check applies to that address rather than to the EVM
caller. Without a permissions namespace it must be the denom admin. With a namespace it must hold
`MINT`, and being the denom admin is not sufficient.

Burns are stricter. They additionally require `allow_admin_burn` on the denom, and `SUPER_BURN` rather
than `BURN` where a namespace exists. See
[mint and burn authority](/developers-evm/erc20-module#mint-and-burn-authority).
</Warning>

## Discovery

On-chain metadata does not make a token appear in dApp frontends, which read from registries.
[injective-lists](https://github.com/InjectiveLabs/injective-lists/blob/master/CONTRIBUTING.md) supplies
logos and labels across Injective dApps, and is documented at
[Injective List](/developers/assets/injective-list).

Symbols are not unique across tokens. Integration instructions identify an asset unambiguously only
by network, bank denom and ERC20 address.

## Markets

A spot market can be created on the native orderbook once supply exists and metadata is set. See
