<a id="chain-upgrades" />

Injective coordinates software upgrades at the block height set by an approved governance proposal. Nodes halt at the activation height. Operators restart with the release specified for that upgrade so their nodes can continue validating and following the chain. Check the [operator portal](https://chain.injective.network/upgrades) for the upgrade schedule and the [Validator Troubleshooting Guide](/infra/coordinated-upgrades) for recovery procedures.

<Warning>
**Mainnet upgrade preparation for v1.21.0.** The [latest release upgrade guide](/infra/validator-mainnet/canonical-chain-upgrade-v1.21.0) contains the published Mainnet binary and verification details. Confirm the enacted proposal, halt height, and coordination announcement on the [operator portal](https://chain.injective.network/upgrades) before upgrading.
</Warning>

<Callout icon="warning" color="#FF8C00" iconType="regular">
**Validators:** Before upgrading, read the [Validator Troubleshooting Guide](/infra/coordinated-upgrades) for critical safety rules, common failure modes, and recovery procedures. Mishandling `priv_validator_state.json` during upgrades can lead to double-signing and permanent tombstoning.

If you are not already a member of the verified validator channels, reach out to the Injective team via [Discord](https://discord.gg/injective) to get added. Upgrade coordination, emergency snapshots, and incident communication happen in these channels.
</Callout>

### Node Upgrade Directions

To summarize, follow these steps to upgrade your node:

1. Sync your node to the block height predetermined by the upgrade governance proposal.
2. The node will automatically panic/stop at the predetermined upgrade height.
3. Remove the old binaries and install the new release binaries.
4. Restart the node.

<Note>
If the upgrade fails or a sentry node becomes corrupted, see the [Snapshots page](https://chain.injective.network/snapshots) for options to resync your node from a fresh snapshot.
</Note>

### Node Maintenance (Managing Storage)

In v1.21.0, `injectived prune` uses the same retention policy for application state, CometBFT blocks, and ABCI responses. It compacts both databases by default. Pass `--force-compact=false` to skip forced compaction. Run `injectived prune --help` to review retention options for your release, and stop the node before running the command. Choose retention based on the history the node needs to serve.

To sync from a recent snapshot, see the [Snapshots page on the Chain Portal](https://chain.injective.network/snapshots) and [Join a Network](/infra/join-a-network).
