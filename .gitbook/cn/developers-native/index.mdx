本节面向使用原生 Cosmos SDK 模块和基于 Go 的工具在 Injective 上构建的开发者。
无论你是在开发自定义模块、查询链状态、构建交易，
还是与 Injective 的核心金融原语集成，
都可以在这里找到原生开发路径的完整技术文档。

Injective 通过专为去中心化金融构建的模块扩展了 Cosmos SDK，
形成了一种模块化架构：每个组件负责特定的职责，同时彼此无缝协作。
`exchange` 模块是 Injective 的核心，它实现了可与中心化交易所媲美的完全链上订单簿交易，
而 `tokenfactory` 等模块支持无需许可的资产创建，`peggy` 则实现了无需信任的 Ethereum 跨链桥。
这种模块化设计使开发者能够利用现有基础设施组合出强大的应用：用于共识的质押、
用于协议升级的治理，以及在 EVM 和 Cosmos 环境之间统一代币余额的原生 bank 模块。
对开发者而言，这意味着可以通过简洁的 Go API、gRPC 端点
和丰富的消息类型使用机构级金融原语，并将它们组合成复杂的交易策略和 DeFi 应用。

## 关键概念 {#key-concepts}

| 术语 | 定义 |
|------|------------|
| **Cosmos SDK Module** | 独立的区块链逻辑单元（例如 `exchange`、`bank`、`staking`），提供特定功能，并通过 inter-module messaging 相互通信。 |
| **Exchange Module** | Injective 的核心模块，支持完全去中心化的现货和衍生品交易，包括链上订单簿管理、订单撮合和结算。 |
| **Keeper** | 模块的核心组件，负责管理状态，并通过定义好的接口暴露业务逻辑，处理读写操作和状态转换。 |
| **Message (Msg)** | 触发模块状态变更的交易类型，例如用于转账的 `MsgSend` 或用于交易的 `MsgCreateSpotLimitOrder`。 |
| **Query** | 在不修改链状态的情况下读取链状态的只读操作，通过 gRPC、REST 和 CLI 接口提供。 |
