本节为在 Injective 交易基础设施上构建的交易者和开发者提供全面的文档。
无论你是通过 API 执行交易、将订单簿功能集成到你的 dApp 中，
还是在了解保证金要求和衍生品，都可以在这里找到
订单类型、费用结构和交易工具的详细规范。

Injective 将中心化交易所的效率
与区块链的透明度和安全性相结合，重新定义了去中心化交易。
通过频繁批量拍卖（FBA），Injective 将订单聚合为离散批次并以单一清算价格执行，
从而消除了矿工可提取价值（MEV）和抢先交易。
与依赖恒定乘积公式流动性池的传统 DEX 不同，
Injective 的链上 CLOB 支持精确的限价单、高级订单类型和机构级执行。
创新的负 maker 费率模式让流动性提供者获得返佣而不是支付费用，从而为做市商创造了强大的激励，
带来比典型去中心化交易所更窄的价差和更深的流动性。

## 关键概念 {#key-concepts}

| 术语 | 定义 |
|------|------------|
| **Central Limit Orderbook (CLOB)** | 一个完全链上的订单撮合系统，与基于 AMM 的 DEX 不同，它在所有 Injective dApp 之间实现透明的价格发现和共享流动性。 |
| **Frequent Batch Auctions (FBA)** | Injective 的订单执行机制，在离散的时间间隔内聚合订单并以统一价格清算，从而消除 MEV 和抢先交易。 |
| **Negative Maker Fees** | 一种费用结构，流动性提供者（maker）获得返佣而不是支付费用（目前符合条件的交易对为 -0.01%），以激励深度的订单簿流动性。 |
| **Perpetual Futures** | 没有到期日的衍生品合约，跟踪标的资产的价格，通常使用资金费率使合约价格与现货市场保持一致。 |
| **Initial/Maintenance Margin** | 开立（初始）和维持（维持）杠杆仓位所需的抵押品；低于维持保证金会触发清算以保护协议。 |
