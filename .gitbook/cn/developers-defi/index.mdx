Injective 是专注于交易所的 Layer-1 区块链的前沿，提供去中心化永续合约、期货和现货交易。它充分利用了去中心化衍生品和无边界 DeFi 的可能性。每个组件都设计为完全无需信任、抗审查、可公开验证和抗抢跑。

Injective 使交易者能够创建和交易任意现货和衍生品市场。Injective 还通过 Injective 链的 [Exchange 模块](/developers-native/injective/exchange) 编码的逻辑实现链上限价订单簿管理、链上交易执行、链上订单匹配、链上交易结算和链上交易激励分配。

与依赖自动做市商（AMM）的其他 DeFi 平台不同，
Injective 提供完全链上的订单簿，撮合引擎能力直接内置于协议层。
这意味着基于 Injective 构建的交易所共享一个全局统一的流动性池，
同时保有各自的 UI 和用户关系，并可从其发起的订单中赚取交易手续费。
凭借对永续合约、期货、现货和二元期权的原生支持，
以及无需许可的市场创建和亚秒级出块时间，
开发者无需构建后端基础设施，也无需担心流动性碎片化，即可发行复杂的交易平台。

## 本节内容 {#what-this-section-covers}

本节面向在 Injective 上构建去中心化金融应用、
交易所和交易基础设施的开发者。
无论你是在发行新代币和市场、构建算法交易策略、集成价格预言机，
还是管理代币元数据，这些指南都提供了利用 Injective 原生 DeFi 原语所需的实用知识。

## 关键概念 {#key-concepts}

| 术语 | 说明 |
|------|-------------|
| **Exchange Module** | Injective 的原生链上模块，完全在链上处理限价订单簿管理、交易执行、订单撮合和结算。 |
| **Denom** | Injective 上的原生代币表示格式（例如 `factory/{creator}/{subdenom}`、`peggy{ethereumAddress}`）。Bank 模块中的所有资产都使用此格式。 |
| **Oracle Provider** | 通过治理注册、向链中继价格馈送的外部方，可支持永续合约和二元期权等自定义市场。 |
| **Token Factory** | 一个原生模块，允许以 `factory/{creator}/{subdenom}` 格式无需许可地创建新代币。 |
| **Tick Size** | 交易市场中价格和数量的最小增量，根据资产价值和小数位数计算。 |

## 在 Injective 上构建订单簿 DEX {#build-an-orderbook-dex-on-injective}

作为鼓励交易所在 Injective 上构建和获取交易活动的激励机制，将订单发起到 Injective 交易所协议共享订单簿的交易所（[阅读更多](/developers-native/injective/exchange)）将获得其发起订单交易费用的一定比例作为奖励。交易所协议为 maker 和 taker 设定了全局最低交易费用。

Injective 激励机制的目标是允许交易所相互竞争，以提供更好的用户体验和更好地服务用户，为全球用户扩大 DeFi 的访问范围。

交易所可以轻松设置客户端（如 Web 或移动端的 UI）和 API 提供商。
