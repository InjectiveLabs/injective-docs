## 代币来源

代币通过以下四种来源之一进入 Injective。来源决定了 denom 格式、由哪个账户控制元数据，以及让代币在 EVM 中可见需要做些什么。

| 起点 | 来源 | Denom | 参考 |
|---|---|---|---|
| 新代币 | **TokenFactory** | `factory/...` | 本页 |
| 现有的 Ethereum ERC20 | **Peggy** | `peggy0x...` | [Bridge & Deploy](/developers-defi/bridge-deploy) |
| 其他 IBC 链上的代币 | **IBC** | `ibc/...` | [IBC 转账](/cn/developers-native/examples/ibc) |
| 部署在 Injective EVM 上的合约 | **Injective EVM** | `erc20:0x...` | [MultiVM Token Standard](/cn/developers-evm/multivm-token-standard) |

每种来源都会产生一个 bank denom。exchange、auction、insurance 和 permissions 模块都基于 bank denom 运行，因此来源不会限制代币之后的用途。[MultiVM Token Standard](/cn/developers-evm/multivm-token-standard) 介绍了其底层模型。

<Note>
合规准入资产遵循下面的 TokenFactory 流程，并在其之上叠加一个 permissions 命名空间。[发行许可型资产](/developers-defi/permissioned-assets)介绍了角色、策略和 KYC 钩子。
</Note>

## 创建时固定的设置

TokenFactory denom 的三项属性一经设置便无法更改。

**小数位数（Decimals）** 在 bank 元数据记录了非零值之后便无法更改。之后的更改会失败并报错 `cannot update denom metadata decimals`，因此错误的值将是永久性的。

**管理员销毁（Admin burn）** 由 `create-denom` 上的 `--allow-admin-burn` 设置，并且只能被关闭。一旦其为 false 或已被禁用，重新启用将会失败。当其为 false 时，任何账户都无法从其他地址销毁代币，而配对的 ERC20 则完全无法销毁，因为 ERC20 的销毁总是以从持有者（而非合约）处销毁的形式到达链上。设置该标志本身并不会授权配对合约进行销毁；这需要 EVM 访问一节中所述的单独原生权限。

**管理员权限（Admin authority）** 一旦放弃便无法恢复。将管理员设置为零地址 `inj1qqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqqe2hm49` 会冻结供应量，这通常正是目的所在。但这也会使 `MsgSetDenomMetadata` 没有任何授权发送者（包括治理），并移除配对 ERC20 所依赖的铸造权限。

## 创建 Denom

创建费用由创建者支付，并且因网络而异。在撰写本文时，主网为 0.1 INJ，测试网为 1 INJ。当前值保存在模块参数中：

```bash
curl --fail --silent --show-error \
  "https://sentry.lcd.injective.network/injective/tokenfactory/v1beta1/params" | jq
```

### Web 应用

[Injective Hub](https://injhub.com/token-factory/) 和 [DojoSwap](https://docs.dojo.trading/) 都可以创建和管理代币，并可为其发行市场。[TokenStation](https://www.tokenstation.app/) 还提供空投和发行工具。

### injectived

```bash
CHAIN_ID="injective-888"
NODE="https://testnet.sentry.tm.injective.network:443"
ADMIN_KEY="admin"
ADMIN=$(injectived keys show "$ADMIN_KEY" -a)
TX="--from=$ADMIN_KEY --chain-id=$CHAIN_ID --node=$NODE --gas-prices=500000000inj --gas=1000000"

# create-denom [subdenom] [name] [symbol] [decimals]
injectived tx tokenfactory create-denom ak "AK Coin" AKK 6 --allow-admin-burn $TX

DENOM="factory/${ADMIN}/ak"
```

Denom 按创建者地址划分命名空间，这使得创建无需许可，并消除了名称冲突。在主网上，对应的值为 `--chain-id=injective-1` 和 `--node=https://sentry.tm.injective.network:443`。

### SDK 与合约

- **TypeScript：** [TokenFactory SDK 示例](/cn/developers-native/examples/token-factory)
- **Wasm 合约：** [`injective-cosmwasm`](https://github.com/InjectiveLabs/cw-injective) 提供了 `create_new_denom_msg`、`create_set_token_metadata_msg`、`create_mint_tokens_msg` 和 `create_burn_tokens_msg`
- **消息参考：** [TokenFactory 消息](/developers-native/injective/tokenfactory/03_messages)

## 元数据

钱包、浏览器和 Solidity 调用方从 bank 元数据中读取名称、符号和小数位数。没有元数据的 denom 会显示为空白，且小数位数为零。

```bash
# set-denom-metadata [description] [base] [display] [name] [symbol] \
#                    [uri] [uri-hash] [denom-unit (json)] [decimals] [shouldDisableAdminBurn]
injectived tx tokenfactory set-denom-metadata \
  "My token description" "$DENOM" AKK "AK Coin" AKK "" "" \
  "[{\"denom\":\"$DENOM\",\"exponent\":0,\"aliases\":[]},
    {\"denom\":\"AKK\",\"exponent\":6,\"aliases\":[]}]" \
  6 false $TX
```

该命令接受十个位置参数。最后一个参数为 `true` 时会永久禁用管理员销毁。

[代币元数据](/cn/developers/assets/token-metadata)记录了各个字段的说明。

## 供应量

```bash
# mint [amount] [receiver]
injectived tx tokenfactory mint "1000000$DENOM" "$ADMIN" $TX

# burn [amount] [burn_from]
injectived tx tokenfactory burn "1000000$DENOM" "$ADMIN" $TX
```

这两个命令都接受两个参数。在 6 位小数的情况下，上述数量代表 1 个代币。

## EVM 访问

在为 TokenFactory denom 注册 ERC20 对之前，它对 MetaMask 或 Solidity 合约是不可见的。

```bash
injectived tx erc20 create-token-pair "$DENOM" --from="$ADMIN_KEY" \
  --chain-id="$CHAIN_ID" --node="$NODE" --gas=3000000 --gas-prices=160000000inj
```

创建代币对要求供应量不为零，因此需在初始铸造之后进行。省略 `--erc20` 时，链会部署一个由代币对创建者拥有的 `MintBurnBankERC20`。如果改为提供合约地址，则需满足更多限制条件，详见 [ERC20 Module](/cn/developers-evm/erc20-module)。

注册代币对不会修改合约、不会授予其任何原生权限，也不会改变由谁控制元数据。它只记录 denom 与地址之间的映射，仅此而已。

<Warning>
ERC20 所有权并不赋予原生铸造权限。预编译合约以**合约地址**作为发送者提交原生铸造，因此原生检查针对的是该地址，而不是 EVM 调用方。没有 permissions 命名空间时，该地址必须是 denom 管理员。存在命名空间时，它必须持有 `MINT`，仅是 denom 管理员是不够的。

销毁的要求更为严格。它们还需要 denom 上启用 `allow_admin_burn`，并且在存在命名空间时需要 `SUPER_BURN` 而非 `BURN`。请参阅[铸造与销毁权限](/cn/developers-evm/erc20-module#铸造和销毁权限)。
</Warning>

## 发现

链上元数据并不会让代币出现在 dApp 前端中，前端是从注册表读取数据的。[injective-lists](https://github.com/InjectiveLabs/injective-lists/blob/master/CONTRIBUTING.md) 为各个 Injective dApp 提供 logo 和标签，相关文档见 [Injective List](/cn/developers/assets/injective-list)。

代币之间的符号并不唯一。集成说明只有通过网络、bank denom 和 ERC20 地址才能明确标识一个资产。

## 市场

一旦存在供应量并设置了元数据，就可以在原生订单簿上创建现货市场。请参阅[发行市场](/cn/developers-defi/market-launch)。
