<Callout icon="info" color="#22C55E" iconType="regular">
**Live on testnet.** These gas heuristics require `fixed_gas_enabled` to be set to `true` in the Exchange module params. This is currently enabled on testnet and will be activated on mainnet via a forthcoming governance params proposal.
</Callout>

This doc contains suggested `gasWanted` values for specific Exchange messages. Values were obtained heuristically
by observing gas consumption during MsgServer execution for a transaction containing a single Msg type. Conceptually,
for any transaction the following formula applies:

```
    tx_gas = ante_gas + msg_gas (+ msg2_gas ...)
```

where `ante_gas` is the gas consumed during `AnteHandler` and the subsequent sum of `msg_gas` is gas consumed
by MsgServer of each particular msg (highest observed `ante_gas` is 120_000).

With `fixed_gas_enabled` set to `true` in Exchange params, the following values can be used as `gasWanted` in order to
ensure a transaction does not run out of gas:

> **Note**: The following values are the fixed gas costs for message execution. Add ante-handler gas to determine the transaction’s total gasWanted.

| Message Type | Fixed Message Gas | Total with 120,000 Ante Allowance |
|---|---:|---:|
| MsgCreateDerivativeLimitOrder | 120,000 | 240,000 |
| MsgCreateDerivativeLimitOrder (post-only) | 140,000 | 260,000 |
| MsgCreateDerivativeMarketOrder | 105,000 | 225,000 |
| MsgCancelDerivativeOrder | 71,000 | 191,000 |
| MsgCreateSpotLimitOrder | 100,000 | 220,000 |
| MsgCreateSpotLimitOrder (post-only) | 120,000 | 240,000 |
| MsgCreateSpotMarketOrder | 50,000 | 170,000 |
| MsgCancelSpotOrder | 71,000 | 191,000 |
| MsgCreateBinaryOptionsLimitOrder | 120,000 | 240,000 |
| MsgCreateBinaryOptionsLimitOrder (post-only) | 140,000 | 260,000 |
| MsgCreateBinaryOptionsMarketOrder | 105,000 | 225,000 |
| MsgCancelBinaryOptionsOrder | 71,000 | 191,000 |
| MsgDeposit | 38,000 | 158,000 |
| MsgWithdraw | 120,000 | 240,000 |
| MsgSubaccountTransfer | 100,000 | 220,000 |
| MsgExternalTransfer | 100,000 | 220,000 |
| MsgIncreasePositionMargin | 65,000 | 185,000 |
| MsgDecreasePositionMargin | 80,000 | 200,000 |

For a GTB (Good-Till-Block) limit order, multiply the fixed message gas by 1.1, equivalent to adding 10%, as defined by `GTBOrdersGasMultiplier = math.LegacyMustNewDecFromStr("1.1")`. Reminder that when adding the ante-handler allowance. the multiplier only applies to the fixed base fee.

**Batch Msg types**

Gas for batch message types varies based on the content of the message itself. Additionally, `ante_gas` scales with the
number of orders (noticeably around 3000 added gas, included in this formula).

`N` - is the number of orders

- `MsgBatchCreateSpotLimitOrders`: `tx_gas = 120_000 + N x 103_000`
- `MsgBatchCancelSpotOrders`: `tx_gas = 120_000 + N x 74_000`
- `MsgBatchCreateDerivativeLimitOrders`: `tx_gas = 120_000 + N x 123_000`
- `MsgBatchCancelDerivativeOrders`: `tx_gas = 120_000 + N x 74_000`
- `MsgBatchCancelBinaryOptionsOrders`: `tx_gas = 120_000 + N x 74_000`

***MsgBatchUpdateOrders***

```go
type MsgBatchUpdateOrders struct {
    Sender string

    SubaccountId                      string             // used only with cancel-all (M - number of markets, N number of orders in a market)
    SpotMarketIdsToCancelAll          []string           // M x N x 71_000
    DerivativeMarketIdsToCancelAll    []string           // M x N x 71_000
    BinaryOptionsMarketIdsToCancelAll []string           // M x N x 71_000

    SpotOrdersToCancel                []*OrderData       // N x 71_000 + N x 3000
    DerivativeOrdersToCancel          []*OrderData       // N x 71_000 + N x 3000
    BinaryOptionsOrdersToCancel       []*OrderData       // N x 71_000 + N x 3000
    SpotOrdersToCreate                []*SpotOrder       // N x 100_000 (120_000 if post-only) + N x 3000
    DerivativeOrdersToCreate          []*DerivativeOrder // N x 120_000 (140_000 if post-only) + N x 3000
    BinaryOptionsOrdersToCreate       []*DerivativeOrder // N x 120_000 (140_000 if post-only) + N x 3000
}
```

For example, let's suppose you want to:

- cancel 3 spot orders in market A
- create 2 derivative orders in market B
- create 1 binary options post-only order in market C
- cancel all orders in spot markets X and Y (2 orders in X and 2 orders in Y)

The resulting gas would be computed as such:

```
    total_gas = 120_000                   // ante_gas base
                + 3 x 71_000 + 3 x 3000   // cancel 3x spot
                + 2 x 120_000 + 2 x 3000  // create 2x derv
                + 140_000 + 3000          // create 1x post-only binary options
                + 4 x 71_000              // cancel-all 4x spot orders
```

which ends up being `1_015_000` gas.
